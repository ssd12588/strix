# 任務指示：PII 與資料外洩稽核

> 用法：`uv run strix --target <目標> --instruction-file ./instructions/pii-audit.md`
>
> ⚠️ 使用前提：目標必須是你**自有資產**，或已取得**書面授權**。請保留授權文件。

---

## 授權聲明

本目標為我方自有資產，已取得書面授權進行安全測試，測試範圍與時間均已約定。
所有測試活動在授權範圍內進行，發現將用於修補而非公開揭露。

---

## 測試重點

請依下列優先順序進行，並在每一項完成後更新涵蓋範圍紀錄：

### 1. PII 洩露與越權存取（最高優先）

- 未授權讀取他人個資：IDOR / BOLA（`/users/{id}`、`/orders/{id}`、`/invoices/{id}` 等）
- 以低權限帳號存取高權限資料（水平／垂直越權）
- 回應中意外包含敏感欄位（身分證號、手機、地址、Email、金融資料、內部 ID）
- 錯誤訊息、偵錯端點、備份檔洩露個資

### 2. 大量資料導出風險

- 分頁／偏移量上限繞過（`limit=100000`、`page=-1`、`offset` 溢出）
- 匯出端點（`/export`、`/download`、`/csv`、`/report`）缺少授權或速率限制
- GraphQL 批次查詢與深度查詢造成大量資料回傳
- 無速率限制導致可自動化枚舉

> **驗證原則**：只需取得 **5–10 筆樣本** 證明可越權取得，**不要真的拉取完整資料集**。

### 3. API 安全（OWASP API Security Top 10）

- 認證與授權缺陷（弱 JWT、可偽造 token、缺少簽章驗證）
- 大量賦值（mass assignment）導致可寫入敏感欄位
- 未文件化的端點、舊版 API（`/v1` vs `/v2`）、除錯端點
- 速率限制與配額缺失

### 4. 資料庫層面

- SQL／NoSQL 注入（含盲注、時間盲注）
- 錯誤訊息洩露結構或資料
- 資料庫管理介面、備份檔、`/dump`、`/.env`、`/backup.sql` 暴露

### 5. 攻擊面分析

- 端點與參數清單（含隱藏與未文件化的）
- 第三方整合與 webhook
- 子網域與相關服務（範圍內）

---

## 執行要求

1. **每個發現都要有可重現的 PoC**：完整請求（含標頭與內容）＋ 回應片段（敏感值請遮蔽中間幾碼）。
2. **不要執行破壞性操作**：不刪除、不修改、不植入後門、不影響服務可用性。
3. **驗證資料量要克制**：見上方「驗證原則」。
4. **發現嚴重問題立即回報**，不必等到最後。
5. **記錄涵蓋範圍**：測過哪些端點、哪些已排除、哪些待確認。

---

## 輸出格式

- 使用繁體中文撰寫（技術名詞、payload、程式碼保留英文）。
- 每個發現包含：標題、嚴重度、CVSS、端點、重現步驟、影響、修補建議。
- 最後提供一份摘要：依嚴重度排序的發現清單，以及未涵蓋的範圍與原因。

---

## 排除範圍

- 不在授權清單中的網域與 IP
- 第三方服務（除非其條款允許）
- 會影響服務可用性的壓力測試
- 社交工程與實體入侵
