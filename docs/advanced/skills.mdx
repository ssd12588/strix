技能是結構化的知識包，讓 Strix 代理在特定漏洞類型、技術與測試方法上具備深入專業。

## 概念

LLM 具備廣泛但淺層的安全知識。它們「知道」SQL 注入，但缺少資深滲透測試人員使用的細膩技巧 —— 解析器怪癖、繞過手法、驗證竅門與串接攻擊。

技能會把這類深入且專業的知識直接注入代理的上下文，把它從通才轉變為當前任務的專家。

## 運作方式

當 Strix 為特定任務生成代理時，會依上下文挑選最多 5 個相關技能：

```python
# 為 JWT 測試建立的代理會自動載入相關技能
create_agent(
    task="Test authentication mechanisms",
    skills=["authentication_jwt", "business_logic"]
)
```

技能會被注入代理的系統提示詞，使其能取得：

- **進階技巧** —— 標準測試之外的非常規手法
- **可用 payload** —— 含變化的實用範例
- **驗證方法** —— 如何確認發現並避免誤報

## 技能分類

### 漏洞

核心漏洞類別與深入的利用技巧。

| 技能                                 | 涵蓋範圍                                               |
| ------------------------------------- | ------------------------------------------------------ |
| `authentication_jwt`                  | JWT 攻擊、演算法混淆、宣告竄改      |
| `idor`                                | 物件參照攻擊、水平／垂直越權   |
| `sql_injection`                       | SQL 注入變體、WAF 繞過、盲注技巧 |
| `xss`                                 | XSS 類型、過濾器繞過、DOM 利用           |
| `ssrf`                                | 伺服器端請求偽造、協定處理器         |
| `csrf`                                | 跨站請求偽造、權杖繞過             |
| `xxe`                                 | XML 外部實體、帶外資料外洩                |
| `rce`                                 | 遠端程式碼執行向量                          |
| `business_logic`                      | 邏輯缺陷、狀態竄改、競態條件       |
| `race_conditions`                     | TOCTOU、平行請求攻擊                       |
| `path_traversal_lfi_rfi`              | 檔案包含、路徑穿越                         |
| `open_redirect`                       | 重新導向繞過、URL 解析技巧                  |
| `mass_assignment`                     | 屬性注入、隱藏參數污染        |
| `insecure_file_uploads`               | 上傳繞過、副檔名技巧                      |
| `information_disclosure`              | 資料外洩、以錯誤訊息列舉                  |
| `subdomain_takeover`                  | 懸置 DNS、雲端資源搶佔                    |
| `broken_function_level_authorization` | 權限提升、角色繞過                    |

### 框架

特定框架的測試模式。

| 技能     | 涵蓋範圍                                     |
| --------- | -------------------------------------------- |
| `fastapi` | FastAPI 安全模式、Pydantic 繞過 |
| `nextjs`  | Next.js SSR/SSG 問題、API 路由安全   |

### 技術

第三方服務與平台安全。

| 技能      | 涵蓋範圍                                               |
| ---------- | ------------------------------------------------------ |
| `supabase` | Supabase RLS 繞過、認證問題                     |
| `firebase` | Firebase Firestore、Storage 規則、Auth 與 Functions |

### 協定

特定協定的測試技巧。

| 技能     | 涵蓋範圍                                         |
| --------- | ------------------------------------------------ |
| `graphql` | GraphQL introspection、批次查詢、resolver 問題 |

### 偵察

被動探索與攻擊面測繪技巧。

| 技能             | 涵蓋範圍                                                        |
| ----------------- | --------------------------------------------------------------- |
| `asset_discovery` | CT、TLS SAN 樞轉、被動 DNS，以及 ASN／IP 資產列舉 |

### 工具

沙箱內核心偵察與掃描工具的 CLI 操作手冊。

| 技能       | 涵蓋範圍                                                |
| ----------- | ------------------------------------------------------- |
| `nmap`      | 連接埠／服務掃描語法與高訊號掃描模式  |
| `nuclei`    | 範本選擇、嚴重度篩選與速率調校 |
| `httpx`     | HTTP 探測與指紋輸出模式            |
| `ffuf`      | 字典模糊測試、比對／過濾策略、遞迴    |
| `subfinder` | 被動子網域列舉與來源控制        |
| `naabu`     | 具明確速率／驗證控制的快速連接埠掃描   |
| `katana`    | 爬取深度／JS／已知檔案行為與陷阱        |
| `sqlmap`    | 用於列舉與受控傾印的 SQLi 流程  |

## 技能結構

每個技能都是一個 Markdown 檔案，並以 YAML frontmatter 提供中介資料：

```markdown
---
name: skill_name
description: Brief description of the skill's coverage
---

# Skill Title

Key insight about this vulnerability or technique.

## Attack Surface
What this skill covers and where to look.

## Methodology
Step-by-step testing approach.

## Techniques
How to discover and exploit the vulnerability.

## Bypass Methods
How to bypass common protections.

## Validation
How to confirm findings and avoid false positives.
```

## 貢獻技能

歡迎社群貢獻。請在合適的分類下建立 `.md` 檔案，並加上 YAML frontmatter（`name` 與 `description` 欄位）。好的技能應包含：

1. **實戰技巧** —— 在實務上可行的手法
2. **實用 payload** —— 可運作的範例與變化
3. **驗證步驟** —— 如何確認而不產生誤報
4. **情境感知** —— 版本／環境專屬的行為
