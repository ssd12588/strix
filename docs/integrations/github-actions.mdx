---
title: "GitHub Actions"
description: "在每個 Pull Request 上執行 Strix 安全掃描"
---

把 Strix 整合進你的 GitHub 流程，在上線前攔下漏洞。

## 基本工作流程

```yaml .github/workflows/security.yml
name: Security Scan

on:
  pull_request:

jobs:
  strix-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Strix
        run: curl -sSL https://strix.ai/install | bash

      - name: Run Security Scan
        env:
          STRIX_LLM: ${{ secrets.STRIX_LLM }}
          LLM_API_KEY: ${{ secrets.LLM_API_KEY }}
        run: strix -n -t ./ --scan-mode quick
```

## 必要的 Secrets

請在儲存庫中加入以下 secrets：

| Secret | 說明 |
|--------|-------------|
| `STRIX_LLM` | 模型名稱（例如 `openrouter/z-ai/glm-5.3`） |
| `LLM_API_KEY` | 你的 LLM 供應商 API 金鑰 |

## 結束碼

發現漏洞時，該工作流程會失敗：

| 代碼 | 結果 |
|------|--------|
| 0 | 通過 —— 沒有漏洞（使用 `--fail-on` 時，代表沒有達到或超過門檻的發現） |
| 2 | 失敗 —— 發現漏洞 |

加上 `--fail-on high`（或 `critical`、`medium`、`low`）可只在達到該嚴重度以上時才失敗。較輕微的發現仍會出現在報告中，因此「通過」不代表完全沒有發現。

## CI 用的掃描模式

| 模式 | 耗時 | 使用時機 |
|------|----------|----------|
| `quick` | 數分鐘 | 每個 PR |
| `standard` | 約 30 分鐘 | 每晚建置 |
| `deep` | 1–4 小時 | 候選發行版 |

<Tip>
PR 請使用 `quick` 模式以保持回饋速度；`deep` 掃描可安排在每晚執行。
</Tip>

<Note>
對於 pull_request 工作流程，Strix 會在 CI／無介面執行時自動使用變更檔案的 diff 範圍。若 diff 解析失敗，請確認有抓取完整歷史（`fetch-depth: 0`），或設定 `--diff-base`。
</Note>
