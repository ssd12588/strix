Strix 可用無介面模式在自動化流程中執行。

## 無介面模式

使用 `-n` 或 `--non-interactive` 旗標：

```bash
strix -n --target ./app --scan-mode quick
```

對於 Pull Request 形式的 CI 執行，Strix 會自動把快速掃描範圍限定在變更的檔案。你也可以強制此行為並明確指定比較基準：

```bash
strix -n --target ./app --scan-mode quick --scope-mode diff --diff-base origin/main
```

## 結束碼

| 代碼 | 意義 |
|------|---------|
| 0 | 未發現漏洞（使用 `--fail-on` 時，代表沒有達到或超過門檻的發現） |
| 1 | 執行錯誤 |
| 2 | 發現漏洞（使用 `--fail-on` 時，代表至少有一項達到或超過門檻） |

若只想在嚴重發現時失敗，請用 `--fail-on` 指定最低嚴重度。較輕微的發現仍會報告，但結束碼為 `0`，因此「通過」不代表報告是空的：

```bash
strix -n --target ./app --scan-mode quick --fail-on high
```

## GitLab CI

```yaml .gitlab-ci.yml
security-scan:
  image: docker:latest
  services:
    - docker:dind
  variables:
    STRIX_LLM: $STRIX_LLM
    LLM_API_KEY: $LLM_API_KEY
  script:
    - curl -sSL https://strix.ai/install | bash
    - strix -n -t ./ --scan-mode quick
```

## Jenkins

```groovy Jenkinsfile
pipeline {
    agent any
    environment {
        STRIX_LLM = credentials('strix-llm')
        LLM_API_KEY = credentials('llm-api-key')
    }
    stages {
        stage('Security Scan') {
            steps {
                sh 'curl -sSL https://strix.ai/install | bash'
                sh 'strix -n -t ./ --scan-mode quick'
            }
        }
    }
}
```

## CircleCI

```yaml .circleci/config.yml
version: 2.1
jobs:
  security-scan:
    docker:
      - image: cimg/base:current
    steps:
      - checkout
      - setup_remote_docker
      - run:
          name: Install Strix
          command: curl -sSL https://strix.ai/install | bash
      - run:
          name: Run Scan
          command: strix -n -t ./ --scan-mode quick
```

<Note>
所有 CI 平台都需要能存取 Docker。請確認你的 runner 已可使用 Docker。
</Note>

<Tip>
若 CI 中的 diff 範圍解析失敗，請抓取完整的 git 歷史（例如 GitHub Actions 的 `fetch-depth: 0`），這樣才能解析 merge-base 與分支比較。
</Tip>
