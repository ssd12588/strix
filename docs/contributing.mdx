## 開發環境設置

### 先決條件

- Python 3.12+
- 最新的 Go 1.24.x 修補版本（僅用於 Bubble Tea TUI 開發與發行產物）
- Docker（需正在執行）
- [uv](https://docs.astral.sh/uv/)
- Git

### 本機開發

<Steps>
  <Step title="複製儲存庫">
    ```bash
    git clone https://github.com/usestrix/strix.git
    cd strix
    ```
  </Step>
  <Step title="安裝相依套件">
    ```bash
    make setup-dev

    # 或手動執行：
    uv sync
    uv run pre-commit install
    ```
  </Step>
  <Step title="設定 LLM">
    ```bash
    export STRIX_LLM="openrouter/z-ai/glm-5.3"
    export LLM_API_KEY="your-api-key"
    ```
  </Step>
  <Step title="執行 Strix">
    ```bash
    uv run strix --target https://example.com
    ```
  </Step>
</Steps>

## 貢獻技能（Skills）

技能是能強化代理能力的專業知識包，放在 `strix/skills/`。

### 建立技能

1. 選擇合適的分類
2. 建立 `.md` 檔案，並加上 YAML frontmatter（`name` 與 `description` 欄位）
3. 附上實用範例 —— 可用的 payload、指令、測試案例
4. 提供驗證方法以確認發現
5. 透過 PR 提交

## 貢獻程式碼

### Pull Request 流程

1. **先建立 issue** —— 描述問題或功能
2. **Fork 並開分支** —— 從 `main` 開始
3. **進行修改** —— 遵循既有程式碼風格
4. **撰寫測試** —— 確保新功能有涵蓋
5. **執行檢查** —— `make check-all` 應通過
6. **提交 PR** —— 連結 issue 並提供背景說明

### 程式碼風格

- 採 PEP 8，每行上限 100 字元
- 所有函式都要有型別提示
- 公開方法要有 docstring
- 函式要小而專一
- 變數名稱要有意義

## 套件建置

可編輯安裝（editable install）不需要 Go，它會直接從原始碼執行 TUI（`go run`）。

Wheel 則是刻意嚴格：一律捆綁對應的 Go sidecar，並且是平台專屬的。

```bash
make wheel
```

建置掛鉤（`scripts/tui_sidecar_hook.py`）需要 Go 1.24.x 或更新版本，會把 sidecar 內嵌為 `strix/bin/strix-tui`，並標上目前平台標籤。由 `scripts/build.sh` 與 `strix.spec` 建置的凍結發行版同樣需要該 sidecar。

## 回報問題

請附上：

- Python 版本與作業系統
- Strix 版本（`strix --version`）
- 使用的 LLM
- 完整錯誤追蹤（traceback）
- 重現步驟
