---
title: "自訂指令"
description: "用自訂測試指令引導 Strix"
---

使用指令可為掃描提供背景資訊、帳號密碼或關注範圍。

## 直接寫在命令列

```bash
strix --target https://app.com --instruction "Focus on authentication vulnerabilities"
```

## 從檔案讀取指令

指令較複雜時，可改用檔案：

```bash
strix --target https://app.com --instruction-file ./pentest-instructions.md
```

## 常見用法

### 認證測試

```bash
strix --target https://app.com \
  --instruction "Login with email: test@example.com, password: TestPass123"
```

### 限定範圍

```bash
strix --target https://api.example.com \
  --instruction "Focus on IDOR vulnerabilities in the /api/users endpoints"
```

### 排除範圍

```bash
strix --target https://app.com \
  --instruction "Do not test /admin or /internal endpoints"
```

### API 測試

```bash
strix --target https://api.example.com \
  --instruction "Use API key header: X-API-Key: abc123. Focus on rate limiting bypass."
```

## 指令檔範例

```markdown instructions.md
# Penetration Test Instructions

## Credentials
- Admin: admin@example.com / AdminPass123
- User: user@example.com / UserPass123

## Focus Areas
1. IDOR in user profile endpoints
2. Privilege escalation between roles
3. JWT token manipulation

## Out of Scope
- /health endpoints
- Third-party integrations
```

<Tip>
指令要具體。好的指令能幫 Strix 優先處理最有價值的攻擊路徑。
</Tip>

## 工作區檔案

指令會成為提示詞的一部分。若要讓 Strix 有檔案可用（例如字典檔、API 規格或筆記），請使用 `--workspace-file`。Strix 會在掃描開始前把檔案放進沙箱工作區。

```bash
strix --target https://app.com --workspace-file ./wordlist.txt
```

檔案會放在 `/workspace/<檔案名稱>`。若要指定目的路徑，請寫成 `PATH:DEST`，其中 `DEST` 是 `/workspace` 內的路徑。

```bash
strix --target https://app.com \
  --workspace-file ./openapi.yaml:specs/openapi.yaml \
  --workspace-file ./notes.md
```

每個要放入的檔案都請重複指定此選項。Strix 會在代理任務中列出這些檔案，代理才知道要到哪裡讀取。

所有工作區檔案都適用以下規則：

- Strix 會把檔案複製進沙箱。代理可以編輯副本，但你機器上的原檔案不會改變。
- 目的路徑必須位於 `/workspace` 內。
- 目的路徑不得落在目標目錄內，因為目標檔案來自目標本身。Strix 會略過這類檔案並記錄警告。
- 兩個檔案不能使用相同的目的路徑。

<Note>
工作區檔案是給代理使用的資料，不是掃描目標，其內容也不會改變指令。
</Note>

<Warning>
不要在工作區檔案中放置機密資訊。沙箱會執行不受信任的目標程式碼，因此請把你放進去的任何內容視為目標可讀取。
</Warning>
