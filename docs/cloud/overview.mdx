## 開始使用

1. 在 [app.strix.ai](https://app.strix.ai) 註冊
2. 連接你的儲存庫，或輸入目標網址
3. 啟動第一次掃描

## 掃描本機原始碼

在不連接原始碼代管平台的情況下，把本機工作目錄送交受管的白箱掃描器：

```bash
# 檢視確切的檔案清單並取得 source.archive_sha256，此時尚未上傳任何內容。
strix cloud scans start --source . --dry-run --show-files --json
SOURCE_SHA256="<reviewed source.archive_sha256>"

# 重複相同來源選擇旗標，並核准該確切快照。
strix cloud scans start --source . --approve-sha256 "$SOURCE_SHA256" --wait
```

在 Git 儲存庫中，Strix 會納入已追蹤的檔案，以及未被忽略的未追蹤檔案。隱藏檔、`.git`、符號連結、相依套件與建置產物、看起來像機密的檔名，以及巢狀壓縮檔預設都會排除。專案專屬的排除規則可使用 `.strixignore`，或重複指定 `--exclude GLOB`。`--include-hidden`、`--include-sensitive` 與 `--include-archives` 必須明確開啟。

CLI 會限制單一檔案大小、展開後的總位元組數、壓縮檔位元組數與檔案數量。若要把工作交給代理或 CI，請重複相同的 `--source`、`--exclude` 與 `--include-*` 旗標，並加上 `--approve-sha256`；若重建的壓縮檔與已檢視的摘要不同，Strix 會拒絕上傳。`--yes` 只代表對「當下建立的快照」核准一次，不是與摘要綁定的兩段式核准。

暫存的本機壓縮檔一定會被刪除。若啟動被明確拒絕，Strix 也會刪除已暫存的遠端上傳。若因網路錯誤、伺服器錯誤或中斷導致啟動結果不明確，Strix 會保留該上傳並回報其 ID；重試前請先以 `strix cloud scans list` 確認，再用 `strix cloud uploads delete UPLOAD_ID` 刪除未連結的上傳。
